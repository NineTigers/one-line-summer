# 올여름 내가 토스할게 저비용 검증 계획

- 문서 상태: v4 활성 기준
- 기준 제품: `docs/PRODUCT-SPEC.md`
- 검증 대상: 재미 주장보다 실제 전송·응답·약속 성사

## 1. 현재 증거

| 증거 | 상태 |
| --- | --- |
| V3 릴레이 인터랙티브 관찰 | 완료 |
| V4 1:1 약속 토스 인터랙티브 관찰 | 없음 |
| 실제 사용자 전송·응답 | 없음 |
| 실제 Apps in Toss 두 기기 테스트 | 없음 |
| 실제 지표·재방문 | 없음 |

`artifact_observation_status`는 현재 V3에 대해 `interactive`, V4에 대해
`not_observed`다. `player_evidence_status`는 `missing`이다.

## 2. 해제할 결정

1. 두 장면을 먼저 좁혀 보내는 방식이 열린 카톡 질문보다 편한가?
2. 받는 사람은 같은 설문이 아니라 실제 답장이라고 느끼는가?
3. 결과가 예쁜 카드가 아니라 날짜와 역할이 있는 약속으로 남는가?
4. 보낸 사람이 답장 확인을 위해 다시 열 이유가 생기는가?
5. 이 가설에 백엔드·아트·출품 시간을 계속 써도 되는가?

## 3. 테스트 대상

서로 실제 연락 가능한 다섯 쌍, 총 10명:

- 친구 2쌍
- 가족 1쌍
- 동료 1쌍
- 연인 또는 매우 가까운 친구 1쌍

조건:

- 한 쌍 안에서 보내는 사람과 받는 사람이 다른 기기를 사용
- 진행자가 상대를 대신 선택하지 않음
- 평소 약속을 잡는 방식이 서로 다른 관계를 포함

## 4. 테스트 빌드

### 필수

- 보내는 사람의 두 장면·날짜·역할 선택
- 실제 공유 가능한 링크
- 받는 사람 전용 화면
- 받는 사람의 장면·날짜·역할 선택
- 서버 `pending → confirmed`
- 보낸 사람 화면의 최신 결과 조회

### 제외

- 알림
- 동적 OG
- 아이콘·썸네일 최종본
- 사진·캘린더·날씨
- 추가 장면

## 5. 진행 방식

### 사전

- 제품 설명을 하지 않는다.
- `여름 약속을 하나 만들어보세요`만 말한다.
- 참여자에게 누구에게 보낼지 미리 정해주지 않는다.
- 개인 메시지 내용은 화면 녹화나 분석에 남기지 않는다.

### 보내는 사람

1. 링크 또는 앱 홈을 연다.
2. 실제로 만나고 싶은 상대를 한 명 떠올린다.
3. 두 장면, 날짜 2~3개, 맡을 일을 고른다.
4. 실제 공유 기능으로 상대에게 보낸다.

측정:

- 첫 선택까지 시간
- 생성 완료 시간
- 실제 전송 여부
- 공유 전 망설임과 수정 횟수

### 받는 사람

1. 실제 받은 링크를 연다.
2. 설명 없이 장면·날짜·맡을 일을 선택한다.
3. 약속을 확정한다.

측정:

- 링크 수신부터 첫 행동까지 시간
- 응답 완료 시간
- 확정 여부
- 뒤로가기·이탈·질문 발생 위치

### 다시 온 보내는 사람

1. 상대가 답했다는 말만 듣고 앱을 다시 연다.
2. 자신의 최근 초대에서 결과를 찾는다.
3. 결과의 장면·날짜·역할을 말한다.

측정:

- 결과 찾기 성공 여부
- 결과 확인 시간
- 날짜·역할 회상

## 6. 관찰 질문

행동이 끝난 뒤에만 묻는다.

### 보내는 사람

- 이 앱에서 방금 무엇을 한 것 같나요?
- 카톡으로 `언제 볼까?`라고 묻는 것보다 편하거나 불편한 점은?
- 상대가 어느 장면을 고를지 궁금했나요?
- 실제로 이 약속을 지킬 가능성이 조금이라도 높아졌나요?
- 다른 사람에게 한 번 더 만들고 싶나요? 누구인가요?

### 받는 사람

- 상대가 무엇을 요청했다고 이해했나요?
- 답하는 과정이 부담스러웠나요?
- 내 선택이 결과를 실제로 바꿨나요?
- 결과에서 확정된 날짜와 서로 맡은 일을 말해 주세요.
- 이 경험을 게임·테스트·초대장·약속 도구 중 무엇이라고 부르겠나요?

### 공통

- 이 앱을 빼고 카톡만 썼을 때와 가장 다른 점은 무엇인가요?
- 가장 지우고 싶은 단계는 무엇인가요?
- 가장 기억나는 한 장면은 무엇인가요?

## 7. 성공 신호

모두 만족해야 개발을 계속한다.

- 5명 중 4명 이상이 실제 상대에게 링크 전송
- 받은 5명 중 3명 이상이 2시간 안에 응답 완료
- 5쌍 중 3쌍 이상이 날짜와 두 역할을 정확히 회상
- 5쌍 중 3쌍 이상이 카톡보다 제안이 구체적이거나 부담이 적다고 설명
- 초대 생성 중앙값 60초 이하
- 응답 중앙값 30초 이하
- 10명 중 8명 이상이 게임·궁합 테스트가 아닌 약속 도구로 설명
- 두 명 이상이 다른 사람에게 새 토스를 실제로 시작

## 8. 실패·중단 신호

하나라도 해당하면 폴리싱 전에 재설계한다.

- 실제 링크 전송이 3건 미만
- 실제 응답이 3건 미만
- 세 명 이상이 `그냥 카톡이 더 빠르다`고 이유까지 설명
- 두 쌍 이상이 결과 날짜나 역할을 회상하지 못함
- 두 명 이상이 선택을 점수·궁합·게임 결과로 오해
- 생성 중앙값 90초 초과
- 받는 사람이 같은 설문을 반복한다고 느낀 사례가 두 건 이상
- 네트워크나 상태 오류로 두 기기 흐름이 한 번이라도 유실

## 9. 결과별 행동

| 결과 | 행동 |
| --- | --- |
| 전송·응답·가치 모두 통과 | V4 P0 개발과 출품 자산 진행 |
| 전송 통과, 응답 실패 | 받는 화면을 2선택+1날짜로 더 축소 |
| 응답 통과, 카톡 차별성 실패 | 최종 결과와 역할 약속을 재설계 |
| 재미 실패, 효용 통과 | 웹툰 공개 연출만 제한적으로 강화 |
| 효용 실패 | 제품 중단, 자산만 보존 |
| 상태 동기화 실패 | 백엔드부터 수정, 아트 중단 |

## 10. 시간·비용 한도

- 첫 검증 빌드: 개발 4시간 이내
- 한 쌍 관찰: 10분 이내
- 다섯 쌍 테스트: 총 2시간 이내
- 결과 정리: 30분 이내
- 최종 아이콘·썸네일 제작: 성공 신호 통과 후

검증을 통과하지 못한 상태에서 선택지·이미지·알림을 추가해 성공을
설명하지 않는다.
