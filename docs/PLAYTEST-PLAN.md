# 올여름 내가 토스할게 저비용 플레이테스트

## 해제할 결정

- 토스와 스파이크가 `둘의 합`으로 이해되는가
- 한 번보다 세 번이 우연을 줄이면서 지루하지 않은가
- 역할을 바꿀 동기가 있는가
- 실제 지인에게 보내고 싶은가

## 증거 상태

- 새 인터랙션 작동본: 없음
- 플레이어 증거: 없음
- 현재 판단 가능한 범위: 기획과 위험
- 판단 불가능한 범위: 손맛, 입력 지연, 재미, 결과 납득감

## 테스트 대상

- 관계가 서로 다른 다섯 쌍
  - 친구 2쌍
  - 동료 1쌍
  - 가족 1쌍
  - 연인 또는 매우 가까운 친구 1쌍

## 테스트 방식

1. 제품 설명 없이 첫 사람에게 기기를 준다.
2. 한 공 버전을 서로 한 번씩 플레이한다.
3. 세 공 버전을 서로 한 번씩 플레이한다.
4. 결과를 본 뒤 아래 질문만 한다.

질문:

- 이 게임에서 두 사람이 무엇을 한 것 같나요?
- 결과 점수가 왜 나왔다고 느꼈나요?
- 혼자 잘한 점수인가요, 둘이 맞춘 점수인가요?
- 실제로 누구에게 보내고 싶나요?
- 답토스를 다시 보내고 싶나요?
- 한 공과 세 공 중 어느 쪽이 더 납득됐나요?

## 성공 신호

- 5쌍 중 4쌍 이상이 `서로 맞춰줌`, `호흡`, `상대 공을 읽음` 중
  하나를 설명 없이 언급
- 5쌍 중 3쌍 이상이 실제 전송 의향을 표시
- 5쌍 중 3쌍 이상이 답토스 의향을 표시
- 첫 입력 방법 이해까지 중앙값 10초 이하
- 한 사람의 공식 플레이 중앙값 30초 이하
- 세 공 버전의 납득도가 한 공보다 높음

## 실패 신호

- 두 쌍 이상이 `그냥 반응속도`, `운`, `왜 궁합인지 모르겠다`고 응답
- 낮은 점수에서 불쾌함이나 관계 판정 부담을 느낌
- 세 공이 반복적이라고 느끼는 사용자가 두 쌍 이상
- 실제 전송 의향이 두 쌍 이하

## 결과별 행동

- 성공: 두 기기 초대 흐름 구현
- 한 공 선호: 공식 기록을 두 공으로 축소해 재검증
- 의미 실패: 점수 개발을 중단하고 공동 결과 생성형 구조로 재설계
- 공유 실패: 앱 출품 우선순위를 모여름으로 집중

## 중단 조건

의미 실패와 앱 유형 미확인이 동시에 남아 있으면 시각 자산 제작과
백엔드 개발을 시작하지 않는다.
