# 한 줄 여름 플레이테스트 계획

- 문서 상태: v5.1 활성
- 목적: 사용자가 설명 없이 한 붓을 그려 건네고, **받은 사람이 이어
  그린 뒤 다시 건네는지** 확인
- 현재 `player_evidence_status`: missing
- 판정 기준: `docs/RISKS-AND-GATES.md` G4

> **v5 초안에서 바뀐 이유.** 이전 판은 중간 분기, 끝점에서 시작,
> 네 획 완성, 순서 재생, PNG 저장을 과업으로 삼았다. 전부 v5.1에서
> 공개 흐름에서 빠진 기능이라 그대로는 테스트를 진행할 수 없다.
> 지금 있는 제품 기준으로 다시 썼다.

## 1. 검증할 가설

### H1 · 한 붓 제한이 부담을 낮춘다

`잘 그려야 한다`는 압박 없이 시작 결정이 쉬워진다. 한 붓 제한이
자유를 빼앗는 규칙이 아니라 안심하게 하는 규칙으로 읽힌다.

### H2 · 예상 밖의 이어 그리기가 감정 사건을 만든다

다음 사람이 내 선을 예상과 다르게 이어붙일 때 웃음·놀람·대화가
생긴다.

### H3 · 받은 사람이 다시 건넨다

**이 제품의 전부다.** 받은 사람이 이어 그리고 멈추면 릴레이가 아니라
일회성 그림 전송이다. 여기서 끊기면 제품 가설이 틀린 것이다.

### H4 · 비게임 경계에서도 다시 열 이유가 있다

점수·보상·승패가 없어도 그림이 어떻게 됐는지 보려고 다시 연다.

> H4는 현재 구조에서 **성립할 근거가 약하다.** 상대가 이어 그려도
> 원래 사람에게 알릴 방법이 없다. 이 테스트의 목적 하나는 H4가
> 실제로 깨지는지 확인해 제품 결정의 근거를 만드는 것이다.

## 2. 참가자

- 5개 그룹, 그룹당 2~4명
- 친구·가족·연인·동료 관계를 섞는다.
- 그림을 즐기는 사람과 부담스러워하는 사람을 모두 포함한다.
- 제작자가 옆에서 설명하지 않는 원격 링크 테스트를 최소 3그룹에
  포함한다.

## 3. 실행 환경

콘솔 등록 전이라 **토스 앱 안에서는 아직 못 돌린다.** 지금 할 수
있는 것은 브라우저 링크 테스트다.

```bash
npm run dev -- --host
```

같은 네트워크의 실제 휴대폰에서 접속해 링크를 메신저로 주고받는다.

이 조건에서 확인되는 것과 안 되는 것을 구분해 기록한다.

| 확인됨 | 확인 안 됨 |
| --- | --- |
| 링크가 실제로 전달되고 열리는지 | 토스 딥링크 진입 |
| 받은 사람이 이어 그리는지 | 토스 네이티브 공유 시트 |
| 다시 건네는지 | 공식 내비게이션 바·뒤로가기 |
| 한 붓 제한을 어떻게 받아들이는지 | 익명 키 발급 |

토스 안에서만 달라질 부분(공유 시트, 뒤로가기)은 실기기 확보 후
다시 본다.

## 4. 테스트 순서

### A. 10초 이해

첫 화면만 보여주고 질문한다.

- 무엇을 하는 앱 같나요?
- 다음에 무엇을 누를 것 같나요?
- 그림을 잘 그려야 할 것 같나요?

### B. 첫 붓

참가자 A에게 별도 설명 없이 첫 붓을 그리게 한다.

관찰:

- 배경 선택에서 망설이는가
- 캔버스에 손대기까지 5초 이상 멈추는가
- 어디서 시작해야 할지 묻는가 (자유 시작이 전달되는가)
- 한 붓만 그려진다는 것을 언제 알아채는가
- 두 번째 붓을 시도했을 때 막힌 것을 실패로 느끼는가
- `다시 그리기`를 스스로 발견하는가
- 그림을 잘 그려야 한다는 부담을 말하는가

### C. 건네기

A가 `친구에게 토스하기`를 누른다.

관찰:

- 저장과 공유가 한 번에 일어난 것을 이해하는가
- 링크를 어디로 보낼지 바로 정하는가
- 누구에게 보낼지 망설인다면 그 이유는 무엇인가

### D. 받은 붓

참가자 B가 **다른 기기에서** 링크를 연다.

관찰:

- 링크가 온전히 전달되는가 (잘리지 않는가)
- 앞사람의 선과 자기 차례를 구분하는가
- 어디에 그릴지 정하는 데 걸리는 시간
- 앞사람 선을 지우거나 고치려 시도하는가

### E. 재토스 — **핵심 관문**

B가 한 붓을 더한 뒤 무엇을 하는지 **개입 없이** 본다.

- 다시 토스하는가, 거기서 멈추는가
- 멈춘다면 이유를 묻는다: 끝났다고 생각했는가, 보낼 사람이 없는가,
  부담스러운가
- 누구에게 보내는가 (A에게 돌려보내는가, 제3자에게 넘기는가)

### F. 릴레이 지속

가능하면 3~4단계까지 이어본다.

- 몇 번째 붓에서 끊기는가
- 그림이 쌓일수록 이어 그리기가 쉬워지는가 어려워지는가
- 링크가 길어져 전달에 문제가 생기는가

### G. 하루 뒤

다음 날 아무 안내 없이 연락해 묻는다.

- 그 그림이 어떻게 됐는지 궁금했나요?
- 다시 열어봤나요? 열어봤다면 무엇을 하려고 열었나요?

H4를 확인하는 유일한 과업이다.

## 5. 기록 항목

### 행동

- 첫 CTA까지 시간
- 유효 첫 붓까지 시간
- 두 번째 붓 시도 횟수
- `다시 그리기` 사용 여부
- 링크 전달 성공 여부와 실패 원인
- 수신 후 이어 그리기 완료 여부
- **이어 그린 뒤 재토스 여부**
- 끊긴 지점의 붓 수
- 다음 날 재방문 여부

`docs/ANALYTICS.md`의 이벤트와 같은 것을 본다. 브라우저 테스트에서는
분석이 나가지 않으므로 관찰로 기록한다.

### 발화

- 웃음·놀람·당황이 발생한 정확한 순간
- `내 선이 이렇게 될 줄 몰랐다`와 유사한 자발 발화
- 한 붓 제한을 규칙으로 말하는가, 제약으로 말하는가
- 그림 실력 평가로 느꼈는지
- 받은 링크가 부담 또는 스팸으로 느껴졌는지
- 기존 메신저 그림 이어그리기와 다른 점

## 6. 판정

### PASS

- 5그룹 중 4그룹 이상이 무설명으로 첫 붓·수신 붓 완료
- 3그룹 이상이 이어 그린 뒤 **실제로 다시 토스**
- 한 붓 제한을 실패가 아닌 규칙으로 받아들임
- 부담·스팸 치명 신호 없음

### PASS_WITH_RISK

- 왕복은 되지만 재토스가 2그룹 이하
- 첫 화면이나 자유 시작에서 마찰이 반복됨

### REWORK

- 받은 사람이 대부분 이어 그리고 멈춘다
- 한 붓 제한이 자유를 빼앗는 규칙으로만 느껴진다
- 링크 전달 실패가 반복된다

### STOP

- 실제 공유가 대부분 부담으로 인식됨
- `그냥 메신저로 그림 보내면 된다`는 평가가 반복됨
- 이어 그리기가 대화나 새로움을 만들지 못함
