## 1. 기술 결정

### 클라이언트

실제 구현은 아래와 같다. 초안의 `React + TypeScript` 계획과 다르다.

- Apps in Toss WebView
- **Vite + 순수 JavaScript.** 화면이 넷뿐이라 프레임워크를 넣지
  않았다. 번들이 작을수록 진입이 빠르다
- `@apps-in-toss/web-framework` 2.10.7
- `npx ait build`로 `.ait` 생성
- Canvas 2D 기반 선 렌더링
- 화면 전환은 섹션 표시/숨김 + `pushState`/`popstate`

### 백엔드

P0 후보는 `Supabase Edge Functions + Postgres`다.

- 지속 운영 서버 프로세스를 직접 관리하지 않는다.
- Postgres가 불변 중간 상태와 부모-자식 관계를 저장한다.
- Edge Function이 공개 토큰·쓰기 검증·속도 제한을 담당한다.
- Realtime은 P0 필수가 아니다. 진입·포그라운드 복귀·사용자
  새로고침 때 최신 자식 가지를 조회한다.

무료 요금제는 검증 단계 후보일 뿐 무중단 운영 보장이 아니다.
휴면, 할당량, 데이터 보존, 상업 이용 조건은 프로젝트 생성 시점의
공식 요금 정책을 다시 확인한다.

## 2. 핵심 불변식

1. 저장된 노드는 수정하지 않는다.
2. 새 붓은 정확히 하나의 부모 노드를 가진다.
3. ~~부모의 마지막 끝점과 새 획의 첫 점이 만난다~~ **삭제.** v5.1은
   캔버스 어디서든 시작한다. 서버가 시작 위치를 검증하지 않는다.
4. (선택) 같은 부모에서 여러 자식을 만들 수 있다.
5. (선택) 한 자식 저장이 형제 자식을 덮어쓰지 않는다.
6. 공개 토큰은 읽기·파생 생성만 허용하고 기존 노드 수정 권한을
   주지 않는다.
7. 클라이언트 URL 상태는 캐시·공유 표현이며 서버가 정본이다.

4번과 5번은 분기를 다시 넣을 때만 필요하다. 다만 append-only 설계는
분기를 쓰지 않아도 그대로 유지한다. 덮어쓰기 사고를 구조적으로
막아준다.

## 3. 데이터 모델

### `canvases`

- `id`: UUID
- `root_node_id`: UUID, nullable until root creation
- `palette_key`
- `prompt_key`
- `creator_user_hash`: nullable
- `created_at`
- `expires_at`
- `status`: active / completed / deleted

### `nodes`

- `id`: UUID
- `canvas_id`
- `parent_node_id`: nullable, root only
- `depth`: 0~12
- `author_alias`: 최대 8자
- `author_slot`: A / B / guest
- `stroke_color_key`
- `stroke_points`: 정규화된 좌표 JSONB
- `endpoint_x`, `endpoint_y`
- `created_at`
- `finished_at`: nullable

노드 하나는 `부모까지의 그림 + 새 붓 하나`를 의미한다. 전체 그림은
루트에서 현재 노드까지 조상 경로를 읽어 재구성한다.

제한은 클라이언트와 같은 값을 쓴다 (`src/link.js`). 현재 최대 12붓,
붓당 30점이다. **서버가 생기면 링크 길이 제약이 사라지므로 이 값을
올릴 수 있다.** 올릴 때 `test/link.test.mjs`의 길이 상한도 함께 본다.

`endpoint_x`, `endpoint_y`는 끝점 이어 그리기를 검증할 때 쓰던
필드다. v5.1에는 그 규칙이 없으므로 넣지 않아도 된다.

### `share_tokens`

- `id`
- `node_id`
- `token_hash`: unique
- `created_by_user_hash`: nullable
- `created_at`
- `expires_at`
- `revoked_at`: nullable

토큰 원문은 생성 응답에서 한 번만 반환하고 DB에는 해시만 저장한다.

### `events`

분석 이벤트는 별도 수집 계층을 우선한다. 사용자 이름, 좌표 원문,
공개 토큰, 익명 키를 분석 속성으로 보내지 않는다.

## 4. API

### `POST /v1/canvases`

- 팔레트·장면·표시 이름·첫 획을 검증한다.
- Canvas와 첫 Node를 한 트랜잭션으로 만든다.
- 첫 Node용 공개 토큰을 반환한다.

### `GET /v1/nodes/by-token/:token`

- 현재 노드와 조상 경로를 반환한다.
- 내부 사용자 키·토큰 해시·분석 식별자를 포함하지 않는다.
- 자식 수나 가지 요약은 반환하지 않는다. v5.1은 이력과 분기 수를
  화면에 노출하지 않는다.

### `POST /v1/nodes/by-token/:token/children`

입력:

- 표시 이름
- 색상 키
- 정규화된 한 획 좌표
- idempotency key

처리:

1. 토큰·만료·depth 확인
2. 점 수·범위·총 payload 제한 확인
3. 부모를 수정하지 않고 새 자식 Node 삽입
4. 새 Node 공유 토큰 생성
5. 동일 idempotency key 재요청이면 기존 자식 반환

시작 위치는 검증하지 않는다. 캔버스 어디서든 시작한다.

### 만들지 않는 것

v5.1 공개 흐름에 없는 기능이라 엔드포인트도 만들지 않는다.

- 분기 조회 (`/branches`)
- 완성 표시 (`/complete`)
- 이력·중간 상태 탐색

## 5. 동시성과 무결성

- `parent_node_id + idempotency_key_hash` unique constraint
- 부모 노드는 행 잠금 없이 읽고 자식만 append
- 같은 부모의 여러 동시 insert는 모두 성공 가능
- 최대 depth·payload·속도 제한은 서버에서 재검증
- 좌표는 0~1 정규화 또는 고정 논리 캔버스 기준으로 저장
- 표시 이름은 제어 문자 제거·길이 제한·HTML 이스케이프
- 완료 요청은 멱등 처리

## 6. Apps in Toss 연동

### 익명 식별

`getAnonymousKey()` 성공 응답의 `hash`를 다시 단방향 해시해 내부
사용자 기준으로 쓴다.

- 별도 로그인 화면 없음
- 조회 실패해도 받은 링크의 열람·한 획 추가는 가능
- 내 최근 작품 복원만 제한

### 공유

정식 경로 예:

`intoss://<appName>/?d=<publicToken>`

프래그먼트가 `deep_link_value`를 거쳐 보존된다는 보장이 없어 쿼리를
쓴다. **아직 실기기에서 확인하지 못했다.**

`getTossShareLink()`로 정식 링크를 만들고 `share()`로 전송한다.
샌드박스 mock과 실제 QR·실기기 증거를 분리한다.

### 내비게이션과 복원

현재 구현은 경로를 나누지 않고 한 페이지에서 화면을 바꾼다. 서버가
생기면 아래 정도만 있으면 된다.

| 경로 | 역할 |
| --- | --- |
| `/` | 직접 진입 |
| `/?d=<token>` | 받은 그림·한 붓 추가 |

`/flow`, `/branches`, `/result`는 v5.1에 없는 화면이다.

## 7. 로컬 프로토타입과 출시 구현의 차이

현재 구현(`index.html`·`src/`)은:

- 전체 문서를 URL에 base64url로 담는다. 웹 링크는 프래그먼트(`#d=`),
  토스 딥링크는 쿼리(`?d=`)를 쓴다.
- 같은 브라우저의 `localStorage`에 생성 노드를 저장한다.
- 공유받은 상대 화면을 새 탭으로 재현한다.

이 방식은 네트워크 없이 UX를 검증하기 위한 것이다. 서로 다른 기기의
`localStorage`는 공유되지 않으므로 실제 협업, 동시성, 원본 갱신,
보안의 증거가 아니다. 출시 버전에서 URL에는 공개 토큰만 두고 좌표와
노드 정본은 Supabase에 둔다.

## 8. 개인정보·보안

- 서비스 역할 키를 클라이언트 번들에 포함하지 않는다.
- RLS를 켜고 Edge Function 외 기존 노드 쓰기를 막는다.
- 공개 토큰은 128비트 이상 무작위 값으로 생성한다.
- 토큰·사용자 키·좌표 원문을 애플리케이션 로그에 남기지 않는다.
- 정확한 위치·연락처·전화번호·사진을 수집하지 않는다.
- 작품 만료·사용자 삭제 경로와 실제 삭제 검증 로그를 둔다.
- 공개 토큰별 생성 속도, IP/익명 키 기반 남용 방지를 적용한다.

## 9. 성능·접근성

- 첫 선택 가능 시점 1초 목표
- 한 붓 payload 32KB 이하 목표 (현재 링크 전체가 열두 붓에도 2KB 미만)
- 결과 렌더링 60fps 목표, 저사양에서 점 간소화
- 320px·390px 가로 스크롤 없음
- 버튼 터치 영역 최소 44px
- 캔버스에 텍스트 상태 안내와 명확한 접근 가능한 이름 제공
- 색만으로 차례를 구분하지 않고 이름·순서를 함께 표시
- `prefers-reduced-motion`에서 반복 펄스 생략
