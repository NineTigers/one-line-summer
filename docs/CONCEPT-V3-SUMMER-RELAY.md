# 올여름 내가 토스할게 v3 — 여름 토스 릴레이 (역사적 제안)

- 문서 상태: 2026-07-26 v4 1:1 약속 토스로 대체됨
- 활성 기준: `docs/PRODUCT-SPEC.md` (v4 1:1 약속 토스)
- 이전 버전: `docs/history/PRODUCT-SPEC-GAME-V1.md` (게임)
- 작성일: 2026-07-26 KST
- 목적: 챌린지 1차 심사(8/1~8/26 지표)에서 이기는 구조 확보

> 보존 이유: 릴레이·URL fragment·재방문 가설과 실제 구현의 차이를
> 추적하기 위한 역사 문서다. 신규 구현 기준으로 사용하지 않는다.

## 1. 한 줄 정의

여름 한 컷을 만들어 친구에게 토스하면, 친구가 자기 컷을 보태
다음 사람에게 토스하며 이어지는 여름 웹툰 릴레이.

## 2. 왜 이 구조인가 — 채점 함수 역산

챌린지 1차 심사는 8월 1~26일 지표다. 앱인토스 비게임 앱의 기본
활성 지표는 `7일 후 재방문`이며, 노출 알고리즘은 활성 사용자와
유사한 사용자에게 앱을 추천한다. 즉 재방문이 노출을 만들고 노출이
다시 재방문을 만드는 복리 구조다.

v2 초대장은 바이럴은 강하지만 1회성 소비라 재방문 이유가 없다.
릴레이는 그 한 칸만 채운다.

| 구조 | 바이럴 계수 | 재방문 이유 | 8월 누적 |
| --- | --- | --- | --- |
| v2 초대장 | 약 1 (1:1) | 없음 | 선형·정체 |
| v3 릴레이 | 1 초과 가능 (트리) | 내 릴레이 성장 확인 | 복리 |

## 3. 비게임 경계

v2의 비게임 원칙을 그대로 승계한다. 릴레이는 도전이 아니라 이어쓰기다.

| 유지 | 금지 |
| --- | --- |
| 참여 인원 사실 표시 | 점수·등급·정확도 |
| 컷 이어붙이기 | 승패·성공·실패 |
| 자동 재생 전환 연출 | 타이밍 입력·판정 |
| 릴레이 길이 표시 | 릴레이 길이 순위·랭킹 |
| 완성 스트립 공유 | 반복 수행 보상·재화 |

`N명이 이어졌어요`는 사실이지 성취가 아니다. 다른 릴레이와 비교하지
않고, 순위표를 만들지 않으며, 길이에 따른 보상이 없다. 시간 제한과
실패 상태가 존재하지 않는다.

챌린지 규정의 `단순 리워드성 미니앱` 배제 조항과도 무관하다.
포인트·출석·룰렛·경품 요소를 두지 않는다.

## 4. 핵심 흐름

### 4.1 진입 — 무마찰 원칙

**프롤로그 화면을 두지 않는다.** 지면에서 탭한 사용자는 첫 화면에서
곧바로 첫 선택지를 만난다. 표지, 설명, 튜토리얼, 이름 입력은 전부
첫 행동 앞이 아니라 뒤에 놓는다.

- 링크로 진입: 앞사람의 컷이 먼저 보이고, 아래에 바로 내 선택지.
- 직접 진입: 첫 화면이 곧 `여름 장면 고르기`.

이름(별칭)은 컷을 다 만든 뒤에 묻는다. 비워두면 `여름 친구`로
자동 표기하고 진행을 막지 않는다.

첫 화면 로딩부터 첫 탭 가능까지 1초를 넘기지 않는다. 표지 이미지
프리로드보다 첫 선택지 렌더링이 우선이다.

### 4.2 내 컷 만들기 (목표 30초 이내)

세 가지만 고른다.

1. 여름 장면 — `한낮의 바다` / `노을` / `여름밤`
   (기존 배경 자산 3종에 그대로 대응)
2. 내가 맡을 것 — 장소 찾기 / 시간 맞추기 / 준비물 / 간식 /
   사진 / 길 찾기 / 음악 / 분위기
3. 한마디 — 선택형 3개 또는 직접 입력 20자

정답이 없고 우열이 없다. 제출 전 자유롭게 수정할 수 있다.

### 4.3 토스하기

`토스하기`를 누르면 공이 화면을 가로지르는 짧은 자동 전환이
재생되고 공유 링크가 만들어진다. 누르는 시점과 속도는 결과에
전혀 반영되지 않는다.

한 사람이 여러 명에게 토스할 수 있다. 체인이 아니라 트리로 자란다.
한 사람이 멈춰도 릴레이 전체가 죽지 않는다.

### 4.4 우리 릴레이 보기

지금까지 이어진 모든 컷을 세로 스크롤 웹툰 스트립으로 본다.
컷과 컷 사이를 공이 날아가는 전환이 잇는다.

맨 아래에 `우리 N명의 2026 여름` 포스터와 공유 버튼이 있다.

### 4.5 여름 카운트다운

스트립 상단에 `올여름이 N일 남았어요`를 표시한다.

이것은 순수 클라이언트 계산이라 백엔드 없이 v1부터 작동하며,
알림이 없어도 다시 열어볼 이유를 만든다. 심사 종료일인 8월 26일은
여름 끝물이자 개학 직전이라, 8월 하순으로 갈수록 이 문구의 압력이
자연히 세진다. 재촉이 아니라 계절 표시로 쓰고, 마감·실패·손실
표현은 쓰지 않는다.

### 4.6 재방문 트리거

재방문 동기를 세 겹으로 둔다. 하나가 막혀도 나머지가 작동한다.

1. 여름 카운트다운 — v1부터, 백엔드 불필요
2. 릴레이 성장 확인 — 링크를 다시 열면 자란 스트립이 보임
3. 알림 — 내 릴레이에 새 컷이 붙으면 발송 (v1.5)

### 4.7 공유 미리보기

공유 링크에는 실제 웹툰 컷이 미리보기 이미지로 붙는다. 메신저에
붙었을 때 보이는 이미지 한 장이 링크 클릭률을 좌우하므로, 텍스트
링크로 나가지 않게 한다.

## 5. 자산 재활용 매핑

템플릿 목록이 수익·결제·게임플레이·알림동의 위주라 불확실하다.

## 9. 기술 구조

### v1 (7/29 등록용) — 백엔드 없음

릴레이 상태를 링크에 인코딩한다. 각 토스마다 앞선 컷들이 압축되어
URL에 누적된다. 서버·DB·개인정보 저장이 없어 3일 안에 확실히
등록 가능하다.

한계: 시작한 사람이 자기 릴레이의 성장을 알림으로 받을 수 없다.

### v1.5 (8월 초) — 최소 백엔드 + 알림

키-값 저장소 하나로 릴레이 노드를 저장하고, 새 컷이 붙으면 알림을
보낸다. 재방문 루프가 여기서 완성된다.

### 중대 리스크

8월 중 번들 업데이트의 검수 소요 기간이 확인되지 않았다. 검수가
길어 8월 업데이트가 불가능하면 v1이 최종본이 되고 재방문 루프가
없는 채로 심사받는다.

대응: v1에 알림이 없더라도 `우리 릴레이 보기`는 반드시 넣는다.
링크를 다시 열면 자란 릴레이를 볼 수 있어야, 알림 없이도 재방문
동기가 최소한 존재한다.

## 10. 지면 전환 최적화 — 1차 심사의 절반

챌린지 출품작은 8월 한 달간 토스 미니앱 메뉴의 챌린지 전용 테마
지면과 큐레이션에 노출된다. 트래픽은 주어진다. 승부는 그 지면에서
탭을 따내고 첫 행동까지 끌고 가는 전환율이다.

따라서 아이콘·썸네일·앱 이름·한 줄 설명은 장식이 아니라 **1차
심사 자산**으로 취급한다. 프론트 개발과 같은 우선순위로 다룬다.

### 전환 퍼널과 목표

| 단계 | 설계 원칙 |
| --- | --- |
| 지면 노출 → 탭 | 썸네일에 사람·감정·여름색. 텍스트 최소 |
| 탭 → 첫 선택 | 프롤로그 없음. 1초 내 첫 선택지 |
| 첫 선택 → 컷 완성 | 3단계 30초. 이름·로그인 요구 없음 |
| 컷 완성 → 공유 | 공유가 종착점이 아니라 흐름의 기본 경로 |
| 공유 → 링크 진입 | 미리보기 이미지에 실제 웹툰 컷 |
| 링크 진입 → 이어쓰기 | 앞사람 컷 바로 아래에 내 선택지 |

### 지면 자산 원칙

- 썸네일 1932×828: 웹툰 한 컷을 그대로 쓴다. 앱 이름을 크게 넣지
  않는다. 지면에 이미 이름이 표기되므로 중복이다.
- 한 줄 설명: 기능이 아니라 행동을 쓴다.
  `친구에게 여름 한 컷을 토스하고, 이어받아 함께 완성해요.`
- 아이콘 600×600: 비치볼 하나. 축소 시 식별되는 단순 형태.
- 스크린샷 3장: 컷 만들기 / 이어진 스트립 / 완성 포스터 순서로
  릴레이 구조가 설명 없이 읽히게 배열한다.
