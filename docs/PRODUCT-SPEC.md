# 한 줄 여름 제품 명세

- 문서 상태: v5 활성 기획 기준선
- 기준일: 2026-07-26 KST
- 제품 책임자: 사용자
- 앱인토스 유형: 비게임
- 현재 판정: `PASS_WITH_RISK`
- 프로토타입 관찰 상태: 인터랙티브
- 실제 사용자 증거: 없음

## 1. 제품 결정

`한 줄 여름`은 한 사람이 남긴 연속선의 끝에서 다음 사람이 선 하나를
이어 공동 그림을 만드는 관계형 비게임 미니앱이다. 완성 전 어느
중간 단계든 여러 사람에게 다시 보낼 수 있고, 같은 선에서 출발한
서로 다른 결과를 나란히 볼 수 있다.

### 한 줄 소개

> 같은 선에서 시작해도 우리마다 다른 여름.

### 사용자 약속

> 그림을 잘 그릴 필요 없이 한 획만 보태고 건네면, 친구마다 다르게
> 이어진 여름을 함께 발견한다.

## 2. 왜 존재하는가

일반 그림 앱은 빈 캔버스와 완성 책임을 한 사람에게 준다. 단순
그림 릴레이는 가장 마지막 결과만 남아 중간 선택의 가능성을 잃는다.
`한 줄 여름`은 다음 세 가지로 문제를 바꾼다.

1. 빈 화면 대신 반드시 앞사람의 끝점에서 시작한다.
2. 한 번에 한 획만 남겨 참여 부담을 작게 만든다.
3. 모든 중간 상태를 다시 공유할 수 있게 해 하나의 시작이 여러
   관계에서 어떻게 달라지는지 보여준다.

재미의 가설은 잘 그린 그림이 아니라 `내 선을 다음 사람이 예상과
다르게 해석하는 순간`과 `같은 출발의 두 결과를 비교하는 순간`이다.

## 3. 대상과 사용 상황

### 핵심 대상

- 친구, 가족, 연인, 동료 중 링크를 주고받을 수 있는 사람
- 그림 실력 평가 없이 가볍게 공동 창작을 하고 싶은 사람
- 여름 안부를 문장보다 작은 행동으로 건네고 싶은 사람

### 대표 상황

- 한 사람이 첫 선을 만들고 단체 채팅의 여러 사람에게 동시에 보낸다.
- 둘이 번갈아 네 획을 완성한 뒤 두 번째 획부터 다른 친구에게 보낸다.
- 같은 중간 선에서 갈라진 결과를 나란히 보고 대화를 시작한다.

### 비대상

- 전문 드로잉·레이어 편집·사진 보정
- 실시간 공동 편집이나 공개 작품 피드
- 점수, 승패, 순위, 보상, 반응속도 경쟁
- AI가 사용자의 선을 대신 완성하는 기능

## 4. 경험 구조

### 4.1 직접 진입

첫 10초 안에 다음을 이해해야 한다.

- 한 번에 한 획만 그린다.
- 앞 선의 끝에서 이어야 한다.
- 중간 선을 여러 사람에게 보내면 다른 결과가 생긴다.

첫 화면의 `같은 시작, 다른 결과 먼저 보기`는 설명보다 실제 두
분기 그림을 먼저 보여준다.

### 4.2 첫 선 만들기

사용자는 여름의 빛과 떠올릴 장면을 하나씩 고른다.

여름의 빛:

- 바다빛
- 소나기빛
- 노을빛
- 여름밤빛

떠올릴 장면:

- 바다 냄새
- 소나기 소리
- 여름밤 공기
- 아무 말 없는 여름

표시 이름은 8자 이내이며 비워두면 `여름 친구`로 쓴다. 장면은
결과를 판정하지 않고 시작점과 색·배경 분위기만 바꾼다.

### 4.3 한 획 잇기

- 빛나는 끝점 가까이에서 입력을 시작해야 한다.
- 손가락을 떼면 그 사람의 한 획이 끝난다.
- 제출 전에는 자기 획만 다시 그릴 수 있다.
- 앞사람의 선은 지우거나 수정할 수 없다.
- 한 획에는 순서, 표시 이름, 역할 색만 기록한다.

입력이 틀렸을 때는 실패·미스·점수를 표시하지 않고 시작점 안내만
다시 보여준다.

### 4.4 건네기

한 획을 저장하면 현재 상태의 공유 링크를 만든다. 링크를 연 사람은
지금까지의 선과 다음 끝점을 먼저 보고 자신의 한 획을 보탠다.

같은 링크를 여러 사람이 열면 모두 동일한 부모 상태에서 시작한다.
각 사람이 저장한 새 획은 부모를 공유하는 서로 다른 자식 가지가
된다. 한 사람의 저장이 다른 사람의 작업을 덮어쓰지 않는다.

### 4.5 중간에서 다시 갈라지기

선의 흐름 화면에는 시작점부터 현재까지 모든 획이 순서대로 보인다.
사용자는 어느 획이든 선택해 그 순간의 링크를 다시 보낼 수 있다.

선택한 중간 상태에서 두 개 이상의 자식 가지가 생기면
`여기서 갈라진 N개 결과 비교하기`를 노출한다. 비교 화면은 최대 두
가지를 먼저 보여주며 어느 쪽도 우승·정답으로 부르지 않는다.

### 4.6 완성과 다시 보기

프로토타입의 최소 완성 조건은 두 사람이 각각 두 번 참여한 네 획이다.
이는 보상 조건이 아니라 두 사람의 왕복을 검증하기 위한 P0 편집
규칙이다. 사용자는 네 획 이후에도 더 건넬 수 있다.

완성 화면은:

- 선이 만난 순서 자동 재생
- 참여자 이름과 여름 장면 문장
- PNG 저장
- 중간 선에서 다른 결과 만들기

를 제공한다. `동작 줄이기` 환경에서는 재생을 생략하고 완성 그림을
즉시 표시한다.

## 5. 비게임 경계

다음 요소는 제품 전 범위에서 금지한다.

- 점수, 등급, 정확도, 성공률
- 타이머, 제한 시간, 반응속도 판정
- 승자, 패자, 순위표, 경쟁 매칭
- 재화, 보상, 출석, 확률형 결과
- 그림 실력·관계 궁합·성향의 자동 판정
- 참여 인원이나 분기 수에 따른 등급 상승

선의 시작점 제약과 한 획 규칙은 공동 창작의 문법이며, 사용자의
성과를 평가하거나 보상하지 않는다.

## 6. 제품 원칙

1. **앞사람의 흔적을 보존한다.**
2. **중간 상태는 완성품만큼 중요하다.**
3. **분기는 복사본이 아니라 부모가 명확한 새 가지다.**
4. **비교는 발견을 위한 것이며 우열을 만들지 않는다.**
5. **공개 피드 없이 의도한 사람에게만 링크를 건넨다.**
6. **직접 입력은 최소화하고 정확한 위치·연락처를 수집하지 않는다.**
7. **실제 기기 공유 증거와 로컬 시뮬레이션을 구분한다.**

## 7. P0와 제외 범위

### P0

- 첫 선과 끝점 기반 한 획 입력
- 불변 중간 상태 저장
- 같은 부모에서 여러 자식 가지 생성
- 공유 딥링크와 받는 사람 화면
- 흐름 탐색과 두 분기 비교
- 네 획 완성·순서 재생·PNG 저장
- 익명 식별·분석·접근성·오류 처리

### P1

- 세 개 이상 분기 탐색 지도
- 완성 결과용 동적 공유 카드
- 오래된 작품의 명시적 삭제
- 초대 도착 알림

### 제외

- 실시간 동시 편집
- 공개 갤러리, 좋아요, 댓글, 팔로우
- 사진·음성·위치 업로드
- AI 자동 완성
- 인앱 결제·광고·리워드

## 8. 현재 구현과 증거

`prototype/`은 URL fragment와 브라우저 `localStorage`로 노드 트리를
재현한 V5 인터랙티브 프로토타입이다.

확인된 항목:

- 390×844, 320×760 레이아웃
- 한 획 입력과 역할 교대
- 동일한 1획 링크에서 서로 다른 2획 두 개 생성
- 공통 부모 화면에서 두 결과 감지·비교
- 네 획 완성과 순서 재생
- 강제 reduced motion
- 브라우저 콘솔 오류·경고 없음

아직 증명하지 못한 항목:

- 서로 다른 실제 기기와 사용자 사이의 데이터 동기화
- Apps in Toss 공유·익명 식별·딥링크
- Supabase 보안·동시성·만료
- 실제 사용자가 재미를 느끼고 다시 공유하는지

따라서 프로토타입은 상호작용 증거이지 출시 가능한 백엔드 증거가
아니다.

## 9. 출시 게이트

1. Supabase에서 같은 부모의 두 자식이 덮어쓰기 없이 저장된다.
2. Apps in Toss 두 실기기에서 생성 → 공유 → 이어 그리기가 된다.
3. 다섯 그룹 중 네 그룹이 설명 없이 첫 획과 이어 그리기를 완료한다.
4. 다섯 그룹 중 세 그룹이 같은 중간 선을 두 명 이상에게 보낸다.
5. 분기 비교 후 세 그룹 이상이 결과 차이를 자발적으로 설명한다.
6. 비게임 검수 문구와 실제 기능에 점수·판정·보상이 없다.

게이트 전에는 “재미가 검증됐다”거나 “우승 가능성이 높다”고
확정하지 않는다.
