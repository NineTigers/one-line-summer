# 콘솔 등록용 지면 자산

토스 미니앱 목록과 챌린지 테마 지면에 **앱 바깥으로** 노출되는
이미지만 둔다.

1차 심사가 8월 지표 기반이고 트래픽 대부분이 테마 지면에서 오므로,
여기 있는 이미지가 곧 전환율이다. 코드와 같은 우선순위로 다룬다.

## 현황

| 자산 | 규격 | 파일 |
| --- | --- | --- |
| 앱 로고 | 600×600 | `icon-600.png` |
| 썸네일 | 1932×828 | `thumbnail-1932x828.png` |
| 스크린샷 1 · 홈 | 636×1048 | `screenshot-1-home.png` |
| 스크린샷 2 · 그리기 | 636×1048 | `screenshot-2-draw.png` |
| 스크린샷 3 · 받은 그림 | 636×1048 | `screenshot-3-received.png` |

규격은 2026-07-26 콘솔 가이드 기준이다. 로고는 투명 배경이 금지고,
세로 스크린샷은 최소 3장이다. **등록 직전에 콘솔에서 다시 확인한다.**

이 자산은 **7/29 첫 등록용 1차본**이다. 아래 `다시 만들어야 하는 때`에
해당하면 다시 찍는다.

## 다시 만들기

```bash
./store/make-assets.sh
```

전부 코드로 그렸다. 비트맵 원본이 없다.

- 로고·썸네일: `icon.source.html`, `thumbnail.source.html`을 헤드리스
  크롬으로 정확한 크기에서 캡처한다.
- 스크린샷: `vite build` 결과물을 임시 폴더로 복사하고 거기에
  `screenshot-*.source.html`을 얹어, 실제 앱을 iframe으로 띄운 채
  찍는다. **제품 코드에는 스크린샷용 분기를 넣지 않는다.**

### 렌더링 함정

- `--force-device-scale-factor`는 레이아웃 뷰포트가 어긋나 오른쪽이
  잘린다. 대신 `--window-size`를 최종 크기로 준다.
- 크롬이 PNG를 다 쓰고도 스스로 끝나지 않을 때가 있다.
  `make-assets.sh`는 파일 크기가 멈추면 프로세스를 끊는다.
- 2번 스크린샷은 그리는 중 상태가 필요하다. 받은 링크로 들어가
  `한 붓 더하기`를 누르고 캔버스에 포인터 이벤트를 흘려, 앱이 스스로
  그린 결과를 찍는다. 좌표를 그림에 직접 심지 않는다.

## 의도

### 스크린샷 순서

홈 → 그리기 → 받은 그림 순서로, 설명 없이도
`한 붓 그리면 링크로 넘어가고, 친구가 한 붓 더해 돌아온다`는 순환이
읽히게 배열했다.

두 번째 장이 가장 중요하다. 한 붓을 그린 직후 `친구에게 토스하기`가
살아 있는 상태이고, 이 제품이 요구하는 유일한 다음 행동이 거기 있다.

### 캡션

앱 안 문구를 그대로 되풀이하지 않는다. 1번은 진입 장벽을 낮추고
(`잘 그리지 않아도 돼요`), 2번과 3번은 주고받는 구조를 설명한다.

### 썸네일

- 앱 이름을 크게 넣지 않았다. 지면에 이미 이름이 표기돼 중복이다.
- 대신 제품의 한 문장 약속을 세 박자로 끊어 썼다.
- 오른쪽에 실제 밑그림과 세 사람의 붓을 놓아, 탭하면 무엇을 하게
  되는지 미리 보여준다.

### 로고

노을 배경에 해 하나와 한 붓. 축소해도 형태가 남도록 굵은 선과 단순한
도형만 썼고 문자를 넣지 않았다.

## 다시 만들어야 하는 때

- 화면 문구나 레이아웃이 바뀌면 스크린샷을 다시 찍는다.
- 밑그림 테마가 바뀌면 썸네일과 스크린샷을 다시 찍는다.
- **실기기에서 공식 내비게이션 바를 붙이면 상단이 달라지므로 전부
  다시 찍는다.**
- 5그룹 플레이테스트에서 캡션이 안 읽히면 캡션부터 고친다.
